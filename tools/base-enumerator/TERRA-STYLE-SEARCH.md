# 시설별 후보·연계 시작점·반복 교체 방식

기존의 모든 보유 조건/해금 상태/시설 구성을 미리 계산하는 방식 대신,
사용자의 **현재 보유·육성 상태와 기지 구성 하나**에 대해 추천을 찾는 실험판이다.
기존 제조소 자료와 확장 자료는 삭제하거나 덮어쓰지 않았다.

## 테라아카이브에서 참고한 구조

참고 페이지: https://terra-archive.net/infra

2026-10-16에 내려받아 두었던 공개 배포 코드 `planner-engine-DV9XFkhq.js`의
시설 편성 함수, 시작 배치 생성 함수, 반복 보정 함수에서 다음 구조를 확인했다.

- 일반 후보의 상위 40명을 기본으로 삼고, 품질·창고 변환 등 연계 후보를 추가로 유지한다.
- 파트너·창고 변환·진영·연계 자원 조합을 시작점으로 둔다.
- 여러 연계 자원/진영 전략으로 배치를 만든 후 점수를 비교한다.
- 시설 인원을 다시 채우거나 다른 시설과 교체하고, 반복 횟수를 제한한다.

2026-10-19에는 실제 페이지도 다시 확인했다. 최신 엔진 파일은 취득하지 못했으므로
현재 최신 버전과 세부 구현이 같다고 주장하지 않는다. 제삼자 JS 번들을 제품에
복사하거나 원격 실행하지 않았고, 위 탐색 구조를 별도 코드로 구현했다.

## 이번 구현

1. 기존 데이터에서 실제 보유 상태에 해금된 시설별 후보를 얻는다.
2. 일반 후보 상위 40명과 지원되는 연계 후보를 유지한다. 이는 휴리스틱 선별이며
   안전한 가지치기 증명이 아니다. 스킬이 같아도 서로 다른 오퍼레이터의 신원은 유지한다.
3. 버메일·버블과 창고 보너스, 샤마르·테킬라·품질 우대, 단독 배치,
   제어센터 진영 효과 등 기존 모델이 지원하는 효과를 시작점으로 삼는다.
4. 사무실→응접실→제어센터 순과 제어센터 우선 순을 사용해 기본 2개 시작 배치를 만든다.
   같은 효과 계열의 시작점은 대표를 추리며 전체 조합을 생성하지 않는다.
5. 구성 단계의 근사 점수로 시설을 채운다. 빈 배치·단독·부분 배치도 허용한다.
6. 시설을 다시 구성하거나 다른 시설/교대조와 인원을 교환한다. 교체 후보의 근사 상위
   6개만 실제 시뮬레이션한다. 상위 6개 제한도 최적해를 잃을 수 있다.
7. 보고할 배치는 기존 `simulate`로 컨디션·숙소·교대·생산·무역을 다시 계산한다.
   실제 시뮬레이션 점수는 사무실→미보유 단서 우대→응접실 속도→생산 순위→무역 순이다.
8. 기본 10초 또는 10,000회 실제 시뮬레이션에서 종료한다. 마지막 시뮬레이션 때문에
   시간 제한을 약간 넘을 수 있다. 준비/데이터 로딩 시간은 별도다.

구성 근사치는 12시간 근무와 6시간 시점의 증가형 스킬을 사용하며,
첫 소진/전원 소진 설정의 실제 근무 시간과 다를 수 있다. 이 근사치로 생산량을 보고하지 않는다.
24시간 기준의 3교대에서 셋째 조의 구성은 보조 비교로 처리한다.
최종 점수가 같으면 구성 근사치·회복/제어 지원·발전소 스킬을 보조적으로 비교한다.
발전소 드론의 24시간 완전한 생산 장부를 추가한 것은 아니다.

작은 사례만 중복 제거 전 조합 상한이 10,000 이하일 때 기존 전수 계산으로 푼다.
시간/평가 제한에 닿으면 전체 검사를 완료한 것으로 표시하지 않는다.
작은 사례의 `modelOptimalityProven`은 지원 모델 내의 완전 탐색만 뜻하고,
게임의 정확성이나 전체 스킬에 대한 최적해 증명이 아니다.

## 실행

```bash
cd tools/base-enumerator
node heuristic-cli.mjs --input examples/quality-trading.json --output my-new-recommendation.json --seconds 10
```

입력은 기존 계산기의 조건 JSON을 그대로 사용한다. `development`는 `current`만 허용하며
전체 보유 조건이나 시설 구성 열거 입력은 거부한다. 기존 출력 파일도 덮어쓰지 않는다.

브라우저에서는 저장소를 내려받은 뒤 해당 디렉터리에서 다음과 같이 실행한다.

```bash
python -m http.server 8000
```

그 후 `http://localhost:8000/heuristic.html`을 연다. 예제를 불러오거나 조건 JSON을
입력하고 배치 계산을 누른다. Web Worker에서 계산하므로 화면 조작과 중단이 가능하다.
결과는 새 JSON으로 내려받는다. 계정 가져오기 UI와 원래 사이트에는 연결하지 않았다.
입력 전송, GitHub Actions 시작, 데이터 삭제, 배포를 자동으로 수행하는 코드는 없다.

## 검증과 측정

재현 명령:

```bash
node --test test.mjs batch.test.mjs trading.test.mjs search.test.mjs parallel.test.mjs resources.test.mjs factory-precompute.test.mjs facility-precompute.test.mjs heuristic.test.mjs
node heuristic-benchmark.mjs --output NEW-BENCHMARK.json
```

Node v24.19.0 / Linux의 한 번 측정한 결과이며 기계별 속도와 제한 시간 내 탐색량은 달라진다.
자세한 입력 생성과 결과는 `heuristic-benchmark.mjs`, `HEURISTIC-BENCHMARK.json`에 있다.

| 사례 | 실제 시뮬레이션 | 경과 시간 | 확인 결과 |
|---|---:|---:|---|
| 작은 무역소·응접실·사무실 전수 검사 | 1,659회 | 약 777ms | 비교 기준 |
| 같은 사례, 강제 휴리스틱 모드 | 22회 | 약 29ms | 위 점수와 일치 |
| 415명 모두 보유·최대 육성, 243 기지 | 121회 | 약 10.00초 | 시작 배치 2개, 보정 1회, 평가 오류 0 |

전체 보유 예제는 실제 개인 계정이 아닌 합성 입력이며 미지원 효과를 제외한다.
전체 보유 예제의 최고 효율이나 정확도 비율은 측정하지 못했다.
전체 회귀 검사 70개가 통과했다. 2/3교대·세 교대 기준·동일 신원 중복·숙소 고정/자동 지원·시간/평가 제한을 검사한다.
새 브라우저 화면의 실제 조작 검사는 수행하지 않았으며, 계산 엔진과 Node 실행 경로를 검증했다.

## 특수 스킬 지원 범위

**이번 변경은 탐색 구조 변경이다. 기존 미지원 스킬을 새로 구현하지 않았다.**
로즈몬티스·슈 등의 연계 자원, 텍사스/라플란드 연계, 프로바이조 주문 변경 등
기존 미지원 효과는 여전히 제외 목록에 남는다. 테라아카이브의 연계 자원 처리 전체나
모든 스킬 계산식을 복제했다고 표현하면 안 된다. 지원 여부는 기존 스킬 규칙을 사용한다.
숙소/응접실 실험식, 주문 기대값 근사, 반복 운영 미검증도 기존과 동일하다.

별도 계산 저장소에만 추가하며 기존 사이트 배포와 장시간 원격 전체 계산은 시작하지 않는다.

# GitHub 원격 계산 설정

공개 저장소의 `ubuntu-latest` 4 vCPU 기준으로 검증 워커 3개를 기본 사용합니다. 4개로 바꿔 같은 조건의 소요 시간을 비교할 수 있습니다. CLI의 `auto`도 4 vCPU에서는 3개를 선택합니다. GitHub에서는 할당 CPU 수보다 많은 워커를 요청해도 CPU 수로 제한합니다.

## 설치 상태와 경로

설정 파일은 작성했지만 GitHub에 업로드하거나 원격 실행하지는 않았습니다.

- 계산기 폴더 → 저장소의 `tools/base-enumerator/`
- 함께 제공한 `infra-compute.yml` → 저장소의 `.github/workflows/infra-compute.yml`

기존 사이트 저장소의 `pages.yml`에는 main push 시 배포하는 규칙이 있습니다. **배포 중단 상태에서는 main에 그대로 올리지 마세요.** 계산 전용 공개 저장소에 위 경로로 넣으면 사이트와 독립적으로 사용할 수 있습니다. 기존 저장소에 넣으려면 기존 배포 워크플로의 자동 실행부터 중단해야 합니다. 이번 작업에서는 기존 배포 설정을 수정하지 않았습니다.

## 시작

1. GitHub에서 **Actions**를 엽니다.
2. **Base optimizer compute (manual)**을 선택합니다.
3. **Run workflow**를 누릅니다.
4. `input_file`에 저장소 안의 조건 JSON 경로를 지정합니다. 기본값은 본인 계정이 아닌 소규모 검증 예제입니다.
5. `workers`는 기본 **3**, `minutes`는 기본 **60**입니다. 한 번의 계산 예산은 최대 300분입니다.
6. 처음 계산할 때 `resume_run_id`는 비웁니다.

서버에서 시작된 뒤에는 본인 컴퓨터를 꺼도 됩니다. 배포·스케줄 실행·다음 작업 자동 호출은 하지 않습니다.

## 저장과 재개

각 실행의 **Artifacts**에서 `infra-compute-state`를 받습니다. 조건 JSON, 결과 NDJSON, 체크포인트, 요약이 들어 있습니다. 보관 기간은 7일이므로 장기 보관할 결과는 내려받으세요.

이어 계산하려면 **Run workflow**에서 `resume_run_id`에 직전 실행 URL `.../actions/runs/123456789`의 숫자를 넣습니다. 직전 실행의 저장 파일을 복원하고, 그때의 정규화된 입력 조건으로 이어갑니다. 재개 시 `input_file`은 사용하지 않습니다. 코드의 계산 버전·스킬 데이터·조건이 달라 호환되지 않으면 재개를 거부합니다.

워커 수와 실행 시간 예산은 재개할 때 변경할 수 있습니다. 현재 검증 묶음을 완료한 뒤 저장하므로 계산 예산보다 조금 더 걸릴 수 있습니다. 강제 취소·런너 장애 시 마지막 체크포인트 이후의 일부 작업은 다시 계산할 수 있습니다. 정상 종료에서는 최종 중간 상태를 업로드합니다. 작업 하나의 제한 전에 저장 시간을 남기도록 계산 예산은 최대 300분, 전체 작업 제한은 350분으로 정했습니다.

원격 실행과 아티팩트 업로드·복원 자체는 실제 GitHub에서 아직 확인하지 않았습니다. 로컬에서는 CPU 배분, 조건 정규화, 서로 다른 워커 수 사이의 CLI 중단/재개를 검증했습니다.

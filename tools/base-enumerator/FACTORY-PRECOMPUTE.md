# 제조소 공통 조합 사전 계산 — 1차 실험

## 결과

지원되는 제조소 스킬을 대상으로 시설 한 곳에 배치하는 조합 자료를 생성했다. 모든 사용자의 보유·해금 조건을 생성하는 이전 방식은 실행하지 않았다. 기존 원격 전수 계산과 사이트 배포는 재가동하지 않았다.

이 측정은 로컬 Linux x64 / Node v24.19.0에서 수행했다. 두 번의 생성 시간은 약 5.26초와 4.79초였고, 비압축 데이터 해시는 같았다. 다른 기기·브라우저·GitHub 실행기의 시간이나 전체 최적화 시간을 보장하지 않는다.

## 보유 조건 적용 실험

자료를 압축 해제·파싱·구조 검증하는 데 179.0ms가 걸렸다. 415명을 모두 보유하고 최종 해금 상태로 설정한 탐침에서는 현재 지원하는 제조소 상태 68개가 선택되고, 3레벨 제조소 후보 52,463개가 남았다. 후보를 필터링하는 데 18.2ms가 걸렸다. 이는 Node 측정이며 브라우저 성능 측정은 아니다. 이 인원 조건에서 미지원 제조소 상태인 22명은 후보에서 제외했다.

## 무엇을 저장했는가

- 오퍼레이터 ID, 동일 인물 ID, 제조소 스킬 ID 조합, 해당 스킬 조합이 나타나는 육성 지점.
- 같은 인물의 다른 해금 상태를 동시에 배치하지 않는 0~3인 조합. 인원이 다른 조합이나 다른 오퍼레이터는 생산 효과가 같아도 삭제하지 않았다.
- 생산 품목 종류에 따른 생산력·창고 용량·컨디션 소모의 공통 계산식. 같은 계산식은 한 번만 저장하고 조합에서 참조한다.
- 발전소 수·무역소 수·숙소 레벨 합·훈련실 레벨·제어센터 효과·근무 누적 시간은 입력 변수로 남겼다. 외부 시설의 모든 경우를 미리 전개하지 않았다.
- 제조소 레벨 1~3은 배치 정원과 기본 창고 용량으로 적용한다. 생산법은 기지 전체의 최고 제조소 레벨이 개방 조건을 충족해야 한다.
- 미지원 상태의 원문 스킬 이름과 설명. 지원되는 낮은 해금 상태는 높은 상태가 미지원이어도 별도 보존한다.

현재 스킬 해금 여부는 사용자 육성 상태로 원본 스킬을 다시 해금해 제조소 스킬 ID가 같은지 비교한다. 제조소에서 스킬이 같은 두 육성 지점을 묶었을 뿐, 다른 시설에서의 효과나 오퍼레이터 신원을 합친 것이 아니다.

## 검증

기존 46개 검사와 새 6개 검사, 합계 52개가 통과했다. 이후 CLI의 조회 시간 측정 기능을 추가하고 새 6개 검사를 다시 통과했다.

1. 작은 7인 풀의 모든 보유 조합과 두 육성 설정, 제조소 레벨 1~3에서 기존 후보 집합과 일치하는지 비교했다.
2. 0~3인 조합의 같은 인물·다른 해금 상태 중복을 검사했다.
3. 모든 지원 스킬 종류의 단독 배치와 표본 3인 조합에 대해, 품목·외부 시설 수·제어센터·누적 근무 시간의 여러 조건에서 기존 효과 계산기와 수치를 비교했다.
4. 버블/버메일 창고 변환과 자동화, 품목별 스킬 제한에 손으로 산출한 값을 대조했다.
5. 작은 5인 풀에서 2교대의 모든 유효 배치를 기존 전수검사와 비교했고, 순금·작전기록의 24시간 점수가 일치했다.
6. 압축 파일 복원, 미완료 파일 거부, 다른 데이터 버전 거부, 미개방 생산법 거부를 검사했다.

기존 계산 모델과 일치한다는 검증이며 실제 게임의 모든 스킬이 정확하다는 뜻은 아니다. 현재 모델의 자동화·피로 등 기존 동작도 유지하며 이 실험에서 게임 규칙을 새로 교정하지 않았다.

## 남은 작업

- 미지원 제조소 스킬 34개 상태를 조사·구현·독립 검증. 현재 자료는 이 효과를 포함하지 않는다.
- 무역소·발전소·사무실·응접실·제어센터·숙소의 공통 후보 자료 구성.
- 여러 시설·교대조의 인원 충돌과 외부 연계를 함께 푸는 최종 탐색기.
- 컨디션 소진 시 기존 시뮬레이터로 되돌아가는 연결. 저장된 식은 배치 인원 전원이 활동 중인 상태만 지원한다.
- 실제 계정 조건에서 전체 시설의 24시간·첫 사이클 성능 및 정확성 측정.

따라서 이번 결과는 제조소 한 곳의 공통 후보 저장이 가능함을 확인한 것이며, 전체 배치 계산기가 수초 만에 끝난다는 근거는 아니다. 생성 자료는 기존 웹사이트나 원격 전수 계산에 자동 연결하지 않았다.
